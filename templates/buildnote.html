beta 0.1.7 — 대시보드 카드별 연도 · 수입금 병합·셀 표시 · 엑셀 내보내기

대시보드 배차·사고·차트 카드마다 연도를 독립으로 바꿀 수 있게 했고, 페이지 전체 새로고침 없이 API로 데이터를 갱신합니다. 수입금은 T머니 CSV와 .dat의 역할을 분리해 (날짜·차번·사번) 기준으로 한 행에 병합하고, 전 기사 공통 사번 정렬·문제 셀만 주황/보라 표시·고정 헤더 스크롤·엑셀 내보내기를 추가했습니다. 상세 집계 규칙은 수입금 집계 기준 탭을 참고하세요.

대시보드 — 카드별 연도·AJAX 갱신

  • 배차 현황 · 사고 현황 · 월별 차트(수입금·배차·사고)마다 독립 연도 선택 — data-dashboard-card (dispatch-status · accident-status · income-chart · dispatch-chart · accident-chart)
  • 연도 변경 시 해당 카드만 갱신 (전체 URL ?year= 새로고침 제거) — 서버 사전 로드 dashboard_payload_by_year + 미캐시 시 /api/dashboard/year/<year>
  • 사고 현황 숫자·차트는 destroy 후 재생성, 배차 현황은 선택 월 기준 지표·전월 대비 증감 유지
  • 초기 데이터는 dashboard-bootstrap-data · dashboard-payload-by-year JSON 스크립트로 전달, 클라이언트 캐시·요청 순번으로 레이스 방지

수입금 — CSV/.dat 병합·사번 정렬

  • T머니 CSV = 실입금·건수·기사 정보 정본, .dat = 출고·입고·시간·연료·거리 — 같은 (날짜·차번·사번)이면 한 행으로 병합 (merge_complementary_sales_rows)
  • 전 기사 공통 사번 정렬 — 당월 CSV 대조 행은 CSV 사번 유지, .dat-only 행은 _align_dat_rows_to_month_csv로 당월 주·야 CSV에 맞춤
  • 업로드·페이지 로드 시 save_sales_data(..., normalize=True) — no_driver_match·잘못된 사번 잔존 행 자동 정리
  • sales_reconcile.py 병합 로직 개선 — T머니/.dat 보유 여부에 따른 역할 분리·보완 필드 복사

수입금 — 셀 색상·표 스크롤

  • 문제 있는 셀만 색상 — 주황 (sales-cell-csv-warn) CSV 0·배차 불일치 · 보라 (sales-cell-dat-warn) .dat 0·CSV 불일치 (compute_sales_cell_warnings)
  • 수동 편집 강조(진한/연한 파랑)와 CSV/.dat 경고 색상 우선순위 분리 — 편집 셀에는 경고색 미적용
  • 업로드 안내 아래 셀 색상 범례 (sales-cell-legend)
  • 표 헤더 고정·본문 스크롤 — sales-table-scroll-head / sales-table-scroll-body (높이 610px), 헤더·본문 열 너비 동기화

수입금 — 엑셀 내보내기

  • /sales/export — 월별·전체 수입 내역 Excel(.xlsx) 또는 CSV 다운로드 (format=xlsx|csv, month=)
  • 화면과 동일 컬럼·표시 형식 (_sales_row_for_export) — 영업시간 등 분 단위 라벨, 사번 정규화
  • 월별 탭 툴바 「엑셀파일(.xlsx)받기」 — 전체 데이터 · 해당 월 링크

beta 0.1.6 — 연도별 데이터 · 대시보드 · 배차·정비 캘린더 · 수입금 편집·이력

배차·사고·기사·차량정비 데이터를 연도별로 분리 저장·조회할 수 있게 확장했습니다. 대시보드도 연도 선택에 맞춰 수입금·배차·사고 지표와 차트를 갱신합니다. 배차와 차량정비는 캘린더를 기본 화면으로 두고, 배차 비고 시트·정비 세부 유형을 화면에 반영합니다. 수입금 표는 수동 수정 셀을 2단계 색상으로 구분하고, 편집 이력·셀 툴팁·통합 검색·페이지네이션을 추가했습니다.

공통 — 연도별 데이터 저장

  • 배차·사고·기사·차량정비 JSON을 연도 키 구조로 저장 (dispatch_data.json, accident_data.json, driver_data.json, car_maintenance_data.json)
  • 엑셀 업로드 시 파일명에서 연도 추출 (extract_dispatch_year_from_filename) — 예: 배차관리_2026.xlsx
  • 기존 단일 연도 JSON은 최초 로드 시 자동 마이그레이션 (레거시 키·단일 파일 → 연도별 맵)
  • 배차·사고·기사·차량정비 화면 상단 연도 선택 드롭다운 — URL ?year= 쿼리와 연동, 업로드 시 선택 연도 유지

대시보드 — 연도별 지표·차트

  • 배차 현황 · 사고 현황 · 월별 차트(수입금·배차·사고) 카드 헤더에 연도 선택 추가 — 배차·사고·수입금 데이터에서 사용 가능한 연도 자동 수집 (_dashboard_available_years)
  • 연도 전환 시 URL ?year= 갱신, 선택 연도의 배차·사고·수입금으로 전체 대시보드 재로드
  • 수입금·연료비 집계를 lease_data.json 대신 수입금 JSON 행 날짜 필드 기준으로 연도별 월 합산 (_build_dashboard_sales_monthly)
  • 배차 현황 — 운전기사·운행일수 및 주간·야간·일차·교대·리스별 기사 수·운행일, 월 이전/다음 전환 시 전월 대비 증감 표시
  • 사고 현황 — 선택 연도 기준 총·미결 건수, 가해(수리지급)·피해(입금) 보상금, 미지급·미입금 견적 합계 (_build_dashboard_accident_summary)
  • 월별 수입금 차트 — 월별 합계 · 누적 평균 · 전체 평균 보조선, Y축 억·천·만 단위 축약 표기
  • 월별 배차 차트 — 근무유형별 누적 영역 + 총 운전기사 막대, 월별 사고 차트 — 가해·피해 막대 + 호버 시 사고원인 비율 툴팁
  • 상단 수입금·연료비 카드는 배차와 별도로 월 탐색 가능 (각 카드 독립 month 상태)

배차 관리 — 캘린더·비고·검색

  • 기본 뷰를 캘린더로 변경 (통계·표는 보조 탭)
  • 엑셀 [비고] 시트 파싱 — 날짜별 대체 · 결근 · 비고를 dispatch_remarks.json에 연도별 저장
  • 캘린더 날짜 클릭 시 하단 패널에 좌측 대체·결근, 우측 비고 표시
  • 근무(O) · 결근(X) · 휴가(/) · 공휴(H) · 예정일(R) 범례, 차량번호 필터, 선택 날짜 강조
  • 캘린더 사이드바 차량 ↔ 기사 토글 — 목록·필터를 차번/차종 또는 사번/이름 기준으로 전환
  • 월간 배차 표 통합 검색 — 쉼표(,)로 다중 조건(차번·차종·근무·사번·이름), 차종은 정확 일치 (K5 ≠ K5H)
  • 연도 툴바 — 보유 연도 목록에서 전환, 업로드 폼에 view_year hidden 전달

차량 관리 — 정비 캘린더

  • 차량정비 탭 기본 뷰를 월별 캘린더로 변경 (통계·표는 보조 탭)
  • 정비 유형 확장: 예방 · 일반 · 사고 · 검사 · 엔진 · 미션 · 교체 · 펑크 · 명일 — 유형별 색상·범례
  • 날짜 클릭 시 해당일 정비 차량·세부 메모(엔진오일, 미션오일, 타이어 교체·펑크 등) 표시
  • 연도·월 선택 — URL ?year= · ?month= 연동, 월별 정비 통계(차종별·유형별 건수) 유지

수입금 관리 — 편집 강조·이력·표 UX

  • 수동 편집 셀 2단계 색상 구분 — 최근 수정 sales-cell-modified-latest (진한 파랑) · 이전 수정 sales-cell-modified-previous (연한 파랑); 새 저장 시 기존 최근 셀은 이전 단계로 자동 강등

  • 셀 호버 시 편집자·수정 일시 툴팁 (data-edit-tooltip, CSS 말풍선)
  • 월별 수정 이력 최대 2건 저장 (edit_history, 기존 last_edit 호환) — 저장 API 응답 field_changes · edit_histories로 저장 직후 강조·이력 UI 갱신

  • 수정 · 저장 · 취소 버튼 분리 — 「수정」 클릭 후 편집 모드 진입 (다른 월 동시 편집 방지), 저장 버튼·이력은 좌측 · 수정/취소는 우측
  • 수입 내역 표 통합 검색 — 쉼표(,) 다중 조건(날짜·차번·차종·근무·사번·운전기사·매칭), 차종 정확 일치 (K5 ≠ K5H)

0.1.2의 .dat 연동을 기반으로, 수입금 관리를 T머니(스마트카드) CSV와 대조하는 집계 체계로 확장했습니다. 같은 차번 주·야 2인 운행도 운전자별로 분리되며, 배차·기사·사고보고서 UI와 수입 차트·표 기능도 함께 보강되었습니다.

집계 정본 (한 줄 요약)

수입금 관리 — T머니 CSV 대조

수입금 집계·표시 — CSV/.dat 병합 · 전 기사 사번 정렬 · 셀 색상 · 표 스크롤

수입금 관리 표의 데이터 병합·매칭·화면 표시 기준을 정비했습니다. T머니 CSV와 미터기 .dat의 역할을 명확히 분리하고, 같은 날·같은 기사는 한 행으로 합칩니다. 사번 불일치(이전월 배차·CSV 차이)는 전 기사 공통 규칙으로 정렬하며, 문제가 있는 셀만 색으로 표시합니다.

한 줄 요약
CSV = 날짜·차번·근무·사번·운전기사·실입금·건수·차종(배차 보조) · .dat = 출고·입고·영업/빈차/총시간·연료·충전량·거리 · 병합 키 = (날짜·차번·사번) · 색상 = 문제 셀만 주황(CSV)·보라(.dat)

1. T머니 CSV vs .dat — 역할 분리

출처 표에 채우는 항목 비고
T머니 CSV 날짜 · 차번 · 근무 · 사번 · 운전기사 · 실입금 · 건수 · 차종(배차 매칭) 정산금액·승인 건수의 정본. CSV 대조된 행은 이름·사번 CSV 우선
미터기 .dat 출고일시 · 입고일시 · 영업시간 · 빈차시간 · 총시간 · 연료비 · 충전량 · 운행거리 · 빈차거리 · 총거리 실입금·건수는 CSV에서만 가져옴 (.dat-only 행은 0)
배차표 근무유형 · 차종 · 차량번호 보조 CSV가 없을 때 기사 매칭. CSV와 다르면 CSV·배차 비교로 주황 표시

CSV와 .dat를 함께 업로드하면 같은 (날짜·차번·사번) 조합의 T머니 항목과 .dat 항목이 한 행으로 병합됩니다. 하루 2줄(실입금만 / .dat만)로 나뉘던 경우가 줄어듭니다.

2. 행 병합 키 — (날짜 · 차번 · 사번)

  • 중복 제거·병합의 1순위 키: (날짜, 차번, 사번)
  • 한쪽에 T머니·한쪽에 .dat만 있어도 사번이 같으면 한 행으로 합침 (merge_complementary_sales_rows)
  • 사번이 다르면 별도 행 유지 — 주·야 2인 차량, CSV/배차 사번 불일치 등
  • 장기 마감 일별 분할(daily_split) 행은 당일 날짜·차번·사번 기준으로 병합

3. 전 기사 CSV·배차 사번 정렬

특정 기사만이 아니라 모든 기사에 동일 규칙을 적용합니다. (예: 당월 CSV 사번 6380, .dat·4월 배차 6370 → 6380 한 행으로 정리)

행 보정 (enrich) → 당월 CSV 사번 정렬 → dedupe 병합 → 매칭·셀 색상 계산
  • CSV 대조 행 (driver · driver_added · car_added · daily): 사번·이름은 CSV 유지, .dat 재매칭 시에도 CSV 사번을 덮어쓰지 않음
  • .dat-only 행: 당월 T머니 CSV에서 같은 날·차번·주·야(근무)에 맞는 사번으로 정렬 (_align_dat_rows_to_month_csv)
  • CSV 대조 시 .dat 재연결: 배차표보다 당월 CSV 주·야에 맞는 운전자를 우선 매칭 (_csv_metrics_for_dat_row)
  • no_driver_match · 잘못된 사번 잔존 행은 페이지 로드·normalize 시 자동 정리 후 JSON 저장
  • 월별 CSV 대조(reconcile_month_rows) 마지막에도 동일 정렬·dedupe 실행
예문 — 사번 변경(6370 → 6380) · 1840호 · 6월
  • 이전: T머니 6380 행 + .dat 6370 행 → 2행
  • 이후: CSV·.dat 병합 → 6380 1행 (실입금·출고일시 동시 표시)
  • 4월처럼 당일 CSV가 없고 .dat만 있는 날은 6370(당월 배차) 행이 남을 수 있음 → 4월 CSV 업로드 시 동일 규칙으로 정리

4. [매칭] 완료 조건

매칭 열은 배차관리 · T머니 CSV · .dat 세 출처에서 날짜 · 차번 · 사번 · 이름을 대조한 결과로 표시합니다. 표시 문구는 완료 또는 실패이며, 텍스트 색상으로 어떤 출처가 어긋났는지 구분합니다.

조건 표시 텍스트 색상

  • 한 출처에 해당 행 데이터가 없으면 그 출처는 대조에서 제외 — 남은 출처끼리만 비교
  • 매칭 열 색상은 행 단위 표시이며, §5 셀 색상(주황·보라)과 별도입니다

예: CSV·.dat는 6380·홍길동으로 일치하는데 배차표만 6370이면 → 실패 (노란색). 세 출처가 서로 다른 기사·차번 조합이면 → 실패 (빨간색).

5. 셀 색상 — 문제 있는 셀만 표시

업로드 안내 아래 범례와 동일합니다. 열 전체가 아니라 해당 셀만 색이 바뀝니다.

수입금 관리 — T머니 CSV 대조 · 운전자 분리 · 집계 보완

수입금 관리 화면과 집계 로직을 정비했습니다. 실입금·건수는 T머니(스마트카드) CSV를 정본으로 쓰고, 영업시간·연료·거리는 .dat에서 가져옵니다. 같은 차번에 주간·야간 2명이 탄 경우에도 운전자별로 행이 분리됩니다.

한 줄 요약
CSV = 실입금·건수 (정산 기준) · .dat = 영업시간·연료·충전량·운행거리 · 배차표 = 근무유형·차종 보조 (이름·사번은 CSV 우선)

1. 업로드 화면 — CSV와 .dat 분리

업로드 모달이 두 단계로 나뉩니다.

구분 파일 역할
① T머니 수입금 상세 CSV 운전자별수입금상세내역 등 (.csv) 실입금·건수의 기준 데이터 (월 1개)
② 미터기 마감 .dat YYYYMMDD_차번4자리_… (복수 선택) 영업시간·연료비·충전량·운행거리 산출
  • 권장: CSV와 .dat를 함께 업로드 → 표·차트에 카드 실입금과 운행 지표가 한 번에 반영
  • CSV만 업로드해도 됨 → 기존 행의 실입금·건만 갱신 (운행 지표는 기존값 유지)
  • .dat만 업로드해도 됨 → 운행 지표만 갱신 (실입금·건수는 CSV 대조 전까지 .dat 기준 또는 0)
  • CSV·.dat 모두 업로드 후 서버에서 자동 삭제 (디스크에 남기지 않음, 메모리에서만 처리)

2. T머니 CSV 형식

형식 파일 예 집계 기준
신형 (16열) 운전자별수입금상세내역 거래일자 · 운전자ID · 차량번호 · 정산금액(14열) · 하차(승인)·승차(승인) 건수
구형 (15열) 일자별상세거래내역 거래시각 → 날짜, 동일 항목·정산금액 규칙 (레거시 호환)

일별 Excel 없이도 신형 CSV만으로 (날짜·차번) 차량 합계와 (날짜·차번·사번) 운전자별 합계를 만들 수 있습니다. 운전자ID 000000(미지정)은 차량 합계 보정 시 기존 행에 합산됩니다.

3. CSV 대조 흐름

.dat 업로드 (선택) → 행 병합·dedupe → CSV 대조 → 운전자별 실입금·건수 반영 → 누락 차량·기사 행 추가 → sales_data.json 저장
  • 같은 날짜·차번·사번 중복 행은 먼저 병합한 뒤 CSV를 적용하고, 적용 후에도 한 번 더 dedupe
  • .dat에 없고 CSV에만 있는 운전자 → driver_added 행 추가 (영업시간 0, 실입금·건수는 CSV)
  • .dat에 있으나 CSV 사번과 안 맞는 행 → 제거 (고아 행)
  • 차량 합계와 운전자 합계 차이 → 영업시간·실입금이 큰 행에 잔차 배분

4. 주간·야간 2인 차량 — 운전자 분리

같은 차번에 주간·야간(또는 교대 2인)이 각각 운행하면 날짜·차번·사번마다 1행씩 저장됩니다. 예: 1814호 4월 1일 → 사번 1563(주간) 1행 + 사번 6144(야간) 1행.

5. 영업시간 0분 표시 개선

.dat의 #3 운행 구간 합이 0이어도 영업시간이 빈칸·0분으로 남지 않도록 3단계 폴백을 적용합니다.

  1. 1순위 — #3 구간별 시간 합
  2. 2순위 — #4 duty on→off 근무시간 (마감 시작~종료 안에서)

수입금 집계 기준 — 영업일 · 실입금 · 건수 · 연료

기존 회사 ERP(엑셀·미터기 프로그램)와 같은 .dat 파일을 쓰더라도, 화면에 보이는 숫자가 다르게 느껴질 수 있습니다. 이 문서는 새 ERP(수입금 관리)가 각 항목을 어떻게 계산하는지, 기존 ERP와 무엇이 같은지·다른지를 예문과 함께 설명합니다. 실입금·건수는 T머니 CSV를 올리면 CSV가 정본이며, .dat는 운행 지표(영업시간·연료·거리)에 씁니다.

한 줄 요약
CSV = 실입금·건수 (T머니 정산금액) · .dat = 영업시간·연료·충전량·운행거리 (마감 1파일 = 1영업일) · 배차표 = 근무·차종 보조 (CSV 대조 후 이름·사번은 CSV 우선)

1. .dat 파일이란?

택시 미터기(스마트카드/TIMS)에서 내려받는 일별 운행 기록 파일입니다. 파일명 예: 20260409_1809_02.dat (날짜_차번4자리_순번). 안에는 보통 아래 네 블록이 들어 있습니다.

블록 내용 새 ERP에서 쓰는 항목
#1 헤더 차량번호, 영업 시작·종료 일시 영업일(날짜), 영업시작·영업종료
#2 운행·요금 승차·하차·정산 등 요금 기록 .dat만 업로드 시 실입금·건수 임시값 (CSV 대조 시 CSV로 교체)
#3 운행 구간 구간별 시간·거리·연료(L) 영업시간(1순위), 운행거리, 충전량
#4 근무 on/off 근무 이벤트 영업시간 2순위 (#3이 0일 때). 장기 마감 일별 분할 시 당일 근무시간
.dat 업로드 → 파싱 (#1~#4) → 마감 영업일 1행 생성 → 배차표와 기사 매칭 → T머니 CSV 대조 (선택) → 표·차트 표시

일반 마감은 .dat 1파일 = 1영업일 1행이며, 달력 “그날 0~24시”만 잘라 합산하지 않습니다. 영업시간이 0으로 나오면 #3 → #4 → #1 헤더 시각 차이 순으로 보완합니다.

2. 영업일(날짜) — 언제 하루치로 잡나?

기존 ERP (엑셀)

  • 회사 정산 기준 영업일에 맞춰 1행 표시
  • 표의 「일」 열 = 그 달의 며칠인지 (1~31)
  • 야간·교대는 전날 밤~다음날 아침도 한 영업일로 묶일 수 있음

새 ERP (수입금 관리)

  • #1 헤더의 종료(end) 일자 = 표의 날짜
  • .dat 1파일 = 1영업일 (마감 1회 = 1행)
  • 파일명 날짜와 다를 수 있음 → 종료 일자가 우선
예문 — 파일명과 영업일이 다른 경우

파일 20260401_1809_01.dat의 헤더를 보면:
시작 2026-03-31 04:59 → 종료 2026-04-01 03:12

새 ERP 표의 날짜는 2026-04-01 (종료일)입니다. 3월 31일 밤부터 이어진 운행도, 이 마감 파일에 포함된 범위면 4월 1일 영업일 1건으로 저장됩니다.

3. 실입금 — 얼마를 합산하나?

2026-07-06부터 T머니 CSV를 업로드하면 표의 실입금·건수는 CSV 정산금액이 정본입니다. 아래 .dat 기준 설명은 CSV 없이 .dat만 올렸을 때 또는 운행 지표 참고용입니다.

기존 ERP

  • 미터금액: 미터기에 찍힌 그 마감 구간 총액
  • 실입금액: 미터금액 − 가불·부족금 등 공제 후 금액
  • 엑셀에서 실입금액 열을 급여·정산에 사용

새 ERP (수입금 관리)

  • CSV 업로드 시: T머니 정산금액(14열) 합 = 표의 실입금
  • 거래일자·운전자ID·차량번호 기준, 운전자별·차량별 집계
  • 가불·부족금 등 미터기 공제는 CSV에 이미 반영된 값을 따름

.dat만 업로드 시 (CSV 대조 전)

  • #2 블록 파일 전체 요금 합이 임시 실입금
  • CSV를 올리면 이 값은 정산금액으로 교체됨
  • 가불·부족금 공제는 반영하지 않음 → 기존 미터금액에 더 가까움

공통 (.dat 운행 지표)

  • 달력 “그날 0~24시”만 필터하지 않음 (마감 파일 전체)
  • 연료·거리·영업시간은 항상 .dat 기준 유지

7. 자주 묻는 질문

  • Q. 같은 .dat인데 예전 ERP 엑셀과 월 합계가 다른데요?
    A. 엑셀에 없는 날짜(23~30일 등)이 있거나, ERP에서 0원인데 .dat만 있는 날(5·12·19일 등)이 있으면 월 합계가 달라집니다. 날짜별로 맞춰 보세요.
  • Q. 리스 차량인데 하루 건수·실입금이 말이 안 되게 큽니다 (예: 278건).
    A. 미터기를 며칠~수 주간 마감하지 않으면 .dat 1개에 여러 날 데이터가 누적됩니다. 영업 구간이 달력 2일 이상 걸치면(3일치 이상) 집계기준=daily_split으로 달력일별 행으로 나눠 저장합니다. 해당 .dat를 다시 업로드하고, 실입금·건수는 CSV도 함께 올려 주세요.
  • Q. 표 숫자를 수정할 수 있나요?
    A. 수입금 관리 표에서 수정·저장 가능합니다. .dat를 다시 올리면 같은 날짜·차번·영업시작(또는 근무·사번) 조합만 덮어씁니다. 주간/야간 2명이 같은 차를 쓰면 사번별 별도 행으로 저장됩니다 (CSV 대조 시 운전자별 분리).
  • Q. 배차만 바꿨는데 수입금 숫자도 바뀌나요?
    A. 아니요. 사번·이름·근무 등 매칭 정보만 갱신됩니다. 단, CSV 대조된 행은 이름·사번이 CSV 우선이라 배차 변경만으로 이름이 바뀌지 않을 수 있습니다. 금액은 CSV·.dat·저장값 기준입니다.
  • Q. T머니 CSV와 .dat 중 무엇을 먼저 올려야 하나요?
    A. 업로드 화면에서 한 번에 함께 선택하는 것이 가장 정확합니다. .dat 병합 후 CSV 대조가 실행되며, CSV에 포함된 월만 실입금·건수가 갱신됩니다.
  • Q. 업로드한 파일이 서버에 남나요?
    A. CSV는 메모리에서만 처리하고 디스크에 저장하지 않습니다. .dat는 처리 중 uploads/dat에 잠시 두었다가 JSON 저장 후 자동 삭제됩니다.
  • Q. 다시 .dat를 올려야 하나요?
    A. 집계 방식이 바뀐 뒤에는 해당 월 .dat를 다시 업로드하면 운행 지표가 새 기준으로 저장됩니다. 실입금·건수까지 맞추려면 T머니 CSV도 함께 올려 주세요.
