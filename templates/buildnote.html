beta 0.1.3 — T머니 CSV 대조 · 수입금 집계 정비 · UI 개선

0.1.2의 .dat 연동을 기반으로, 수입금 관리를 T머니(스마트카드) CSV와 대조하는 집계 체계로 확장했습니다. 같은 차번 주·야 2인 운행도 운전자별로 분리되며, 배차·기사·사고보고서 UI와 수입 차트·표 기능도 함께 보강되었습니다.

집계 정본 (한 줄 요약)
T머니 CSV = 실입금·건수 · .dat = 영업시간·빈차·연료·충전량·거리 · 배차표 = 근무유형·차종 보조 (CSV 대조 후 이름·사번은 CSV 우선)

수입금 관리 — T머니 CSV 대조

  • 업로드 화면 2단 분리: ① 운전자별수입금상세내역 CSV · ② 미터기 .dat (복수)
  • CSV·.dat 함께·개별 업로드 가능 (CSV만 → 실입금·건수 갱신, .dat만 → 운행 지표 갱신)
  • 신형 CSV(16열) · 구형 일자별상세(15열) 자동 판별, cp949 인코딩 (tmoney_parser.py)
  • 대조 흐름: 행 dedupe → CSV 적용 → 운전자별 실입금·건수 → 누락 차량·기사 행 추가 → 저장 (sales_reconcile.py)
  • 처리 후 CSV·.dat 파일 서버 자동 삭제 (메모리 처리, 디스크 미보관)
  • 내부 필드 T머니출처: driver · driver_added · daily · car_added · no_tmoney

수입금 관리 — 주·야 2인 차량 운전자 분리

  • 배차 lookup: 동일 차번에 근무유형 + 사번 조합으로 다중 기사 보관
  • 매칭 시 행 사번 우선, 없으면 영업시작 시각(주/야)으로 선택
  • CSV 대조 행은 CSV 사번·이름 유지 — 배차표 이름으로 덮어쓰지 않음
  • 같은 날짜·차번·사번 중복 행(dat 다중 마감) 병합 후 CSV 적용

수입금 관리 — .dat · 장기 마감 · 영업시간

  • 일반 마감: .dat 1파일 = 1영업일 1행 (#1 헤더 종료일 = 표 날짜)
  • 장기 마감(영업 구간 2일+): 달력일별 1행 분할, 출고·입고 시각 클립, 당일 #3/#4 기준 지표
  • 영업시간 3단계 폴백: #3 구간 합 → #4 on→off → #1 헤더 시각 차이
  • 표 열 확장: 출고일시 · 입고일시 · 영업시간 · 빈차시간 · 총시간 · 빈차거리 · 총거리
  • 인라인 편집: 실입금·건수·영업·빈차·연료·충전량·거리 (총시간·총거리 자동 합산)
  • 영업시간 열 data-sort-minutes 숫자 정렬, 일자 범위 슬라이더·합계 행

수입금 관리 — 차트·분석 (0.1.2 이후)

  • 복합 막대 차트 — 실입금 + 영업시간(분) + 실입금 평균선 (이중 Y축)
  • 필터: 차번 · 차종 · 사번 · 운전기사 · 근무유형 (표 필터·차트 연동)
  • 산점도 — 실입금 vs 연료비 (차종·근무 체크박스 필터)
  • 파이 차트 — 차종별 평균 실입금·연료비, 실입금 순위 요약표 (1~3위 배지)

배차 관리

  • 월간 배차표 좌측 5열 고정 (차번~기사), 인정·승무·결근·휴가 집계열 배경 강조
  • data-col 기준 통합 검색, 차종 정확 일치 (K5 ≠ K5H)
  • 검색 시 표 min-height 고정, 일별 근무 색상·업로드 이력 드롭다운

운전기사 관리

  • 거주지 열 숨김, 근무유형 → 근무 짧은 표시
  • 쉼표 다중 검색 (사번·이름·근무·차종), 날짜·사번 표시 정리, 프로필 링크

사고 보고서 (가해 / 피해)

  • A4 인쇄 레이아웃, 결재란, 가해·피해 템플릿 섹션 재구성
  • 약도 + 사고경위 좌우 배치, Cloudtype·로컬 약도 경로 자동 분기

빌드노트 · 운영

0.1.3 선행 — 수입금 차트 강화 · 배차·기사·사고보고서 개선

수입금 관리 분석 탭의 차트·필터를 대폭 확장하고, 배차·기사 목록 UI·검색을 정비했으며, 교통사고보고서 인쇄 양식을 A4 기준으로 재구성했습니다.

수입금 관리 — 차트·분석 강화

  • 복합 막대 차트 — 실입금(막대) + 영업시간(분)(라인) + 실입금 평균선(점선) 이중 Y축
  • 차트 필터 드롭다운: 차번 · 차종 · 사번 · 운전기사 · 근무유형 (전체/개별 선택, 표 필터와 연동)
  • 산점도 — 실입금 vs 연료비, 차종·근무 조합별 색상·범례, 체크박스로 차종·근무 필터 (전체 선택/해제)
  • 파이 차트 — 차종별 평균 실입금·연료비 분포
  • 실입금 순위 요약표 (1~3위 금·은·동 배지), 일자 범위 슬라이더·표 합계 행
  • 표에 근무유형 열 추가, 정렬·인라인 편집·업로드 이력 드롭다운 유지

배차 관리

  • 월간 배차표 좌측 5열 고정 (차번~기사) + 인정·승무·결근·휴가 집계열 배경 강조
  • 통합 검색: data-col 기준 (짧은 헤더 표시와 무관), 쉼표 다중 조건
  • 차종 정확 일치 (K5 ≠ K5H), 검색 시 표 높이 고정으로 화면 흔들림 방지
  • 일별 근무 색상 (o 녹색 · x 빨강 · / 주황 · H 공휴), 업로드 이력 드롭다운

운전기사 관리

  • 목록에서 거주지 열 숨김, 근무유형 → 근무 짧은 표시
  • 통합 검색: 사번 · 이름 · 근무(주간·야간·일차·교대·리스·월차) · 차종 (쉼표 다중, 근무·차종 정확 일치)

사고 보고서 (가해 / 피해)

  • A4 인쇄 레이아웃 (794×1123px), 결재란 (담당 · 상무 · 부사장 · 대표)
  • 가해·피해 템플릿 분리 재구성: 기본정보 · 보상/현황 · 대인 · 대물 · 가해차량(피해) 섹션
  • 행 높이·열 너비 통일 (row-fixed), 긴 텍스트 2줄 클램프 (cell-long)
  • 사고 현장 약도 + 사고경위 좌우 배치, Cloudtype·로컬 약도 경로 자동 분기
  • 치료견적·수리추산 금액 천 단위 콤마, 하단 경찰서·조사관·사고번호·처리여부

beta 0.1.2 — 스마트카드 .dat → 수입금 연동

택시 미터기(스마트카드/TIMS)에서 내려받은 .dat 파일을 수입금 관리 메뉴에 업로드하면 일별 수입 데이터로 자동 변환·저장됩니다. 배차 데이터와 연동해 기사 정보를 매칭합니다.

수입금 관리 — .dat 업로드

  • 미터기 .dat 파일 복수 선택·일괄 업로드 (파일명 예: YYYYMMDD_차번4자리_…)
  • 대량 업로드 시 진행률 표시 (배치 API, NDJSON 스트림)
  • 업로드 후 sales_data.json에 월별(01월~12월)로 병합 저장

.dat에서 자동 추출·계산 (마감 영업일 기준)

  • 영업일(날짜) — #1 헤더 종료(end) 일자 (= 미터 마감일, .dat 1파일 = 1영업일)
  • 실입금 — #2 운행·요금 블록 파일 전체 합계
  • 건수 — 파일 #2 전체 영업(요금) 건수
  • 영업시간 — 일반 마감: #3 구간 합. 장기 마감 일별: #4 on→off 근무시간(분)
  • 건수(장기 마감) — 당일 시작 #3 운행 구간 수 (ERP 카드횟수와 동일 체계). 연속 마감 파일의 겹치는 시작일은 제외
  • 운행거리·충전량 — #3 구간 파일 전체 합
  • 연료비 — 업로드 시 입력한 연료 단가(원/L) × 충전량
  • 영업 시작·종료 시각 (#1 헤더)

배차 데이터 연동

  • 행 날짜 기준 해당 월 배차표와 차번(4자리) 매칭
  • 자동 보정: 사번·이름·차종, 매칭 상태 완료 / 미매칭
  • 사번 소수점 제거 (6228.0 → 6228)

조회·편집·분석

  • 월별 탭, 통합 검색 (날짜·차번·사번·이름·차종·매칭)
  • 표 셀 인라인 편집 및 저장 API
  • 차번·사번·이름·차종 필터, 일별·기사별 **수입 차트**
  • 업로드 완료 요약: 파일 수, 전체 건수, 기사 매칭 건수

기술

  • dat_parser.py — UTF-8/cp949 인코딩, #1~#4 블록 파싱
  • 업로드 이력 UploadRecord (type: sales) DB 저장

beta 0.1.1 — ERP 베타 최초 공개

택시 회사 업무를 웹에서 통합 관리하는 ERP 베타 버전을 공개했습니다. 엑셀·.dat 업로드 기반으로 데이터를 저장·조회합니다.

대시보드

  • 월별 실입금·연료비 요약 (전월 대비 증감)
  • 배차 현황: 근무 유형별(주간·야간·일차·교대·리스) 배차일수·기사 수
  • 사고 현황: 가해/피해·미결 건수, 수리·치료·보상 금액
  • 월별 수입금·배차·사고 통계 차트 (Chart.js)

배차 관리

  • 월별(01월~12월) 엑셀 → 월간 배차현황 저장·조회
  • 일별 근무: o(승무), x(결근), /(휴가), H(공휴일)
  • 날짜별·근무유형별 배차 현황 통계표

급여 계산 (리스)

  • 월별 시트 엑셀 (실입금, 리스료, 연료비)
  • 급여 = (실입금 − 리스료 − 연료비) × 0.8
  • 기사별 급여·실입금 표, 급여 순위 차트, 월별 평균·최고·최저

수입금 관리

  • 택시 미터 .dat 업로드 (단건·일괄, 진행률)
  • 연료 단가 → 연료비 자동 산출, 영업분 표시
  • 배차 데이터 자동 매칭 (사번·이름·차종, 완료/미매칭)
  • 월별 탭, 차트 필터, 표 셀 인라인 편집·저장

사고 관리

  • 엑셀 가해사고 / 피해사고 시트 분리 저장
  • 가해/피해 목록, 통계·분석(기사별·차량별), 통합 검색
  • 사고 보고서 인쇄 (/accident/print/...)

수입금 관리 — T머니 CSV 대조 · 운전자 분리 · 집계 보완

수입금 관리 화면과 집계 로직을 정비했습니다. 실입금·건수는 T머니(스마트카드) CSV를 정본으로 쓰고, 영업시간·연료·거리는 .dat에서 가져옵니다. 같은 차번에 주간·야간 2명이 탄 경우에도 운전자별로 행이 분리됩니다.

한 줄 요약
CSV = 실입금·건수 (정산 기준) · .dat = 영업시간·연료·충전량·운행거리 · 배차표 = 근무유형·차종 보조 (이름·사번은 CSV 우선)

1. 업로드 화면 — CSV와 .dat 분리

업로드 모달이 두 단계로 나뉩니다.

구분 파일 역할
① T머니 수입금 상세 CSV 운전자별수입금상세내역 등 (.csv) 실입금·건수의 기준 데이터 (월 1개)
② 미터기 마감 .dat YYYYMMDD_차번4자리_… (복수 선택) 영업시간·연료비·충전량·운행거리 산출
  • 권장: CSV와 .dat를 함께 업로드 → 표·차트에 카드 실입금과 운행 지표가 한 번에 반영
  • CSV만 업로드해도 됨 → 기존 행의 실입금·건만 갱신 (운행 지표는 기존값 유지)
  • .dat만 업로드해도 됨 → 운행 지표만 갱신 (실입금·건수는 CSV 대조 전까지 .dat 기준 또는 0)
  • CSV·.dat 모두 업로드 후 서버에서 자동 삭제 (디스크에 남기지 않음, 메모리에서만 처리)

2. T머니 CSV 형식

형식 파일 예 집계 기준
신형 (16열) 운전자별수입금상세내역 거래일자 · 운전자ID · 차량번호 · 정산금액(14열) · 하차(승인)·승차(승인) 건수
구형 (15열) 일자별상세거래내역 거래시각 → 날짜, 동일 항목·정산금액 규칙 (레거시 호환)

일별 Excel 없이도 신형 CSV만으로 (날짜·차번) 차량 합계와 (날짜·차번·사번) 운전자별 합계를 만들 수 있습니다. 운전자ID 000000(미지정)은 차량 합계 보정 시 기존 행에 합산됩니다.

3. CSV 대조 흐름

.dat 업로드 (선택) → 행 병합·dedupe → CSV 대조 → 운전자별 실입금·건수 반영 → 누락 차량·기사 행 추가 → sales_data.json 저장
  • 같은 날짜·차번·사번 중복 행은 먼저 병합한 뒤 CSV를 적용하고, 적용 후에도 한 번 더 dedupe
  • .dat에 없고 CSV에만 있는 운전자 → driver_added 행 추가 (영업시간 0, 실입금·건수는 CSV)
  • .dat에 있으나 CSV 사번과 안 맞는 행 → 제거 (고아 행)
  • 차량 합계와 운전자 합계 차이 → 영업시간·실입금이 큰 행에 잔차 배분

4. 주간·야간 2인 차량 — 운전자 분리

같은 차번에 주간·야간(또는 교대 2인)이 각각 운행하면 날짜·차번·사번마다 1행씩 저장됩니다. 예: 1814호 4월 1일 → 사번 1563(주간) 1행 + 사번 6144(야간) 1행.

이전 동작 (문제)

  • 배차 매칭이 차번만 보고 첫 번째 기사 이름으로 덮어씀
  • CSV 운전자명이 무시되어 같은 기사 2행처럼 보이는 경우 발생
  • 동일 차번·동일 근무유형(교대) 2인이 lookup에서 1명만 남음

현재 동작 (2026-07-06)

  • 배차 lookup: 근무유형 + 사번 조합으로 다중 기사 보관
  • 매칭 시 행의 사번 우선, 없으면 영업시작 시각(주/야)으로 선택
  • CSV 대조된 행(T머니출처 있음)은 CSV 사번·이름 유지
  • driver_added 행도 CSV 운전자ID를 사번으로 사용
예문 — 1814호 / 2026-04-01 (CSV 대조 후)
사번 이름 실입금 건수 영업시간 출처
1563 CSV 운전자명 242,412 14 0분 (CSV만) driver_added
6144 이관노 207,050 16 630분 (.dat) driver

운전기사 마스터·배차표의 이름과 CSV 이름이 다를 수 있습니다. 실입금·건수·이름은 CSV가 정본이며, 배차표는 근무유형·차종 보조에만 씁니다.

5. 영업시간 0분 표시 개선

.dat의 #3 운행 구간 합이 0이어도 영업시간이 빈칸·0분으로 남지 않도록 3단계 폴백을 적용합니다.

  1. 1순위 — #3 구간별 시간 합
  2. 2순위 — #4 duty on→off 근무시간 (마감 시작~종료 안에서)
  3. 3순위 — #1 헤더 영업시작~종료 시각 차이 (분)

표의 영업시간 열 정렬도 숫자(분) 기준으로 동작합니다. 0분 표시 시 올바른 순서로 정렬됩니다.

6. 표 정렬·편집 (sales.html)

  • 영업시간 셀에 data-sort-minutes 속성 → 분 단위 숫자 정렬
  • 실입금·건수·연료비·충전량·운행거리도 콤마 제거 후 숫자 비교
  • 인라인 편집 후에도 정렬용 분 값 자동 갱신

  • Q. 실입금이 .dat와 다른데요?
    A. 정상입니다. 표의 실입금·건수는 T머니 CSV(정산금액) 기준입니다. .dat #2 합계는 미터기 내부 합산이라 카드 정산과 다를 수 있습니다.

  • Q. 업로드한 CSV 파일이 사라졌어요.

수입금 집계 기준 — 영업일 · 실입금 · 건수 · 연료

기존 회사 ERP(엑셀·미터기 프로그램)와 같은 .dat 파일을 쓰더라도, 화면에 보이는 숫자가 다르게 느껴질 수 있습니다. 이 문서는 새 ERP(수입금 관리)가 각 항목을 어떻게 계산하는지, 기존 ERP와 무엇이 같은지·다른지를 예문과 함께 설명합니다. 실입금·건수는 T머니 CSV를 올리면 CSV가 정본이며, .dat는 운행 지표(영업시간·연료·거리)에 씁니다.

한 줄 요약
CSV = 실입금·건수 (T머니 정산금액) · .dat = 영업시간·연료·충전량·운행거리 (마감 1파일 = 1영업일) · 배차표 = 근무·차종 보조 (CSV 대조 후 이름·사번은 CSV 우선)

1. .dat 파일이란?

택시 미터기(스마트카드/TIMS)에서 내려받는 일별 운행 기록 파일입니다. 파일명 예: 20260409_1809_02.dat (날짜_차번4자리_순번). 안에는 보통 아래 네 블록이 들어 있습니다.

블록 내용 새 ERP에서 쓰는 항목
#1 헤더 차량번호, 영업 시작·종료 일시 영업일(날짜), 영업시작·영업종료
#2 운행·요금 승차·하차·정산 등 요금 기록 .dat만 업로드 시 실입금·건수 임시값 (CSV 대조 시 CSV로 교체)
#3 운행 구간 구간별 시간·거리·연료(L) 영업시간(1순위), 운행거리, 충전량
#4 근무 on/off 근무 이벤트 영업시간 2순위 (#3이 0일 때). 장기 마감 일별 분할 시 당일 근무시간
.dat 업로드 → 파싱 (#1~#4) → 마감 영업일 1행 생성 → 배차표와 기사 매칭 → T머니 CSV 대조 (선택) → 표·차트 표시

일반 마감은 .dat 1파일 = 1영업일 1행이며, 달력 “그날 0~24시”만 잘라 합산하지 않습니다. 영업시간이 0으로 나오면 #3 → #4 → #1 헤더 시각 차이 순으로 보완합니다.

2. 영업일(날짜) — 언제 하루치로 잡나?

기존 ERP (엑셀)

  • 회사 정산 기준 영업일에 맞춰 1행 표시
  • 표의 「일」 열 = 그 달의 며칠인지 (1~31)
  • 야간·교대는 전날 밤~다음날 아침도 한 영업일로 묶일 수 있음

새 ERP (수입금 관리)

  • #1 헤더의 종료(end) 일자 = 표의 날짜
  • .dat 1파일 = 1영업일 (마감 1회 = 1행)
  • 파일명 날짜와 다를 수 있음 → 종료 일자가 우선
예문 — 파일명과 영업일이 다른 경우

파일 20260401_1809_01.dat의 헤더를 보면:
시작 2026-03-31 04:59 → 종료 2026-04-01 03:12

새 ERP 표의 날짜는 2026-04-01 (종료일)입니다. 3월 31일 밤부터 이어진 운행도, 이 마감 파일에 포함된 범위면 4월 1일 영업일 1건으로 저장됩니다.

3. 실입금 — 얼마를 합산하나?

2026-07-06부터 T머니 CSV를 업로드하면 표의 실입금·건수는 CSV 정산금액이 정본입니다. 아래 .dat 기준 설명은 CSV 없이 .dat만 올렸을 때 또는 운행 지표 참고용입니다.

기존 ERP

  • 미터금액: 미터기에 찍힌 그 마감 구간 총액
  • 실입금액: 미터금액 − 가불·부족금 등 공제 후 금액
  • 엑셀에서 실입금액 열을 급여·정산에 사용

새 ERP (수입금 관리)

  • CSV 업로드 시: T머니 정산금액(14열) 합 = 표의 실입금
  • 거래일자·운전자ID·차량번호 기준, 운전자별·차량별 집계
  • 가불·부족금 등 미터기 공제는 CSV에 이미 반영된 값을 따름

.dat만 업로드 시 (CSV 대조 전)

  • #2 블록 파일 전체 요금 합이 임시 실입금
  • CSV를 올리면 이 값은 정산금액으로 교체됨
  • 가불·부족금 공제는 반영하지 않음 → 기존 미터금액에 더 가까움

공통 (.dat 운행 지표)

  • 달력 “그날 0~24시”만 필터하지 않음 (마감 파일 전체)
  • 연료·거리·영업시간은 항상 .dat 기준 유지
예문 — 1809호 / 2026-04-09 (.dat #2 vs 기존 ERP, CSV 대조 전 참고)
구분 금액(원) 설명
.dat #2 실입금 284,654 #2 파일 전체 합 (CSV 대조 전)
기존 ERP 미터금액 285,700 엑셀 「미터금액」 — 차이 약 0.4%
기존 ERP 실입금액 284,620 공제 후 — 새 ERP와 거의 동일한 날도 있음

이 예문은 .dat #2 합계와 기존 ERP를 맞춰 본 참고 자료입니다. T머니 CSV를 업로드한 뒤 표에 보이는 실입금·건수는 CSV 정산 기준이며, 위 .dat 수치와 다를 수 있습니다.

숫자가 안 맞을 때 확인할 것
① T머니 CSV를 올렸는지 (올렸다면 실입금·건수는 CSV 기준) ② 같은 .dat·같은 CSV 월인지 ③ 기존 ERP에서 그날이 0원·빈칸인데 새 ERP에만 있는지 ④ 4/13처럼 ERP가 여러 마감을 한 줄에 합친 특수일인지 ⑤ 주·야 2인 차량인데 운전자별 CSV 대조가 안 된 경우 (같은 차번 1행만 보임)

4. 건수 — 무엇을 세나?

2026-07-06부터 CSV 업로드 시 건수는 T머니 CSV의 하차(승인)·승차(승인) 건수 합입니다. .dat #2 건수와 다를 수 있습니다.

기존 ERP

  • 엑셀 카드횟수 등 — 카드 결제·정산 횟수 기준
  • 회사 정산 프로그램 고유 규칙이 있을 수 있음

새 ERP — CSV 업로드 시

  • T머니 CSV 하차(승인)·승차(승인) 건수 합
  • 운전자ID·거래일자·차번별 집계

.dat만 업로드 시

  • #2에서 영업(요금) 건수
  • 요금 0원 레코드로 승차~정산 구간을 나눠 1건으로 카운트
  • 마감 파일 전체 기준

  • 건수 = 해당 달력일에 시작하는 #3 운행 구간 수
  • 실입금·건수는 CSV 대조 시 CSV 값으로 덮어씀
예문 — 2026-04-09 / 1809호 (.dat #2 건수 vs 기존 ERP 카드횟수)
항목 건수
.dat #2 건수 34
기존 ERP 카드횟수 20

.dat #2 건수와 기존 ERP 「카드횟수」는 정의가 다릅니다. CSV 업로드 후 표의 건수는 T머니 승인 건수이므로, 위 34건 예시와 달라질 수 있습니다.

5. 연료(충전량 · 연료비)

기존 ERP

  • 엑셀 연료사용 (L) — 회사 입력·미터 연동 값
  • 연료비는 별도 단가·정산 규칙 적용

새 ERP

  • 충전량 = #3 구간 파일 전체 연료(L) 합
  • 연료비 = 업로드 시 입력한 연료 단가(원/L) × 충전량
  • 단가는 업로드 화면에서 매번 지정 (예: 1,103원/L)
예문 — 2026-04-09 / 1809호 / 연료 단가 1,103원
항목 값
충전량 (.dat #3 합) 108.31 L
연료비 (108.31 × 1,103) 119,466원
기존 ERP 연료사용 55 L

연료도 실입금과 같이 마감 파일 전체 vs 회사 엑셀 입력값 차이가 날 수 있습니다. 업로드할 때 넣은 연료 단가가 바뀌면 연료비만 달라지고, 충전량(L)은 .dat 기준으로 같습니다.

7. 자주 묻는 질문

  • Q. 같은 .dat인데 예전 ERP 엑셀과 월 합계가 다른데요?
    A. 엑셀에 없는 날짜(23~30일 등)이 있거나, ERP에서 0원인데 .dat만 있는 날(5·12·19일 등)이 있으면 월 합계가 달라집니다. 날짜별로 맞춰 보세요.
  • Q. 리스 차량인데 하루 건수·실입금이 말이 안 되게 큽니다 (예: 278건).
    A. 미터기를 며칠~수 주간 마감하지 않으면 .dat 1개에 여러 날 데이터가 누적됩니다. 영업 구간이 달력 2일 이상 걸치면(3일치 이상) 집계기준=daily_split으로 달력일별 행으로 나눠 저장합니다. 해당 .dat를 다시 업로드하고, 실입금·건수는 CSV도 함께 올려 주세요.
  • Q. 표 숫자를 수정할 수 있나요?
    A. 수입금 관리 표에서 수정·저장 가능합니다. .dat를 다시 올리면 같은 날짜·차번·영업시작(또는 근무·사번) 조합만 덮어씁니다. 주간/야간 2명이 같은 차를 쓰면 사번별 별도 행으로 저장됩니다 (CSV 대조 시 운전자별 분리).
  • Q. 배차만 바꿨는데 수입금 숫자도 바뀌나요?
    A. 아니요. 사번·이름·근무 등 매칭 정보만 갱신됩니다. 단, CSV 대조된 행은 이름·사번이 CSV 우선이라 배차 변경만으로 이름이 바뀌지 않을 수 있습니다. 금액은 CSV·.dat·저장값 기준입니다.
  • Q. T머니 CSV와 .dat 중 무엇을 먼저 올려야 하나요?
    A. 업로드 화면에서 한 번에 함께 선택하는 것이 가장 정확합니다. .dat 병합 후 CSV 대조가 실행되며, CSV에 포함된 월만 실입금·건수가 갱신됩니다.
  • Q. 업로드한 파일이 서버에 남나요?
    A. CSV는 메모리에서만 처리하고 디스크에 저장하지 않습니다. .dat는 처리 중 uploads/dat에 잠시 두었다가 JSON 저장 후 자동 삭제됩니다.
  • Q. 다시 .dat를 올려야 하나요?
    A. 집계 방식이 바뀐 뒤에는 해당 월 .dat를 다시 업로드하면 운행 지표가 새 기준으로 저장됩니다. 실입금·건수까지 맞추려면 T머니 CSV도 함께 올려 주세요.
